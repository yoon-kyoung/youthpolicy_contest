## 1. `on.policylab.co.kr` GitHub 연결 상태 점검

- 이 저장소(`youthpolicy_contest`)의 GitHub Pages 커스텀 도메인이 `on.policylab.co.kr`로 설정돼 있음을 확인 (`gh api repos/yoon-kyoung/youthpolicy_contest/pages` → `cname: "on.policylab.co.kr"`, `status: null`)
- 문제: 이 도메인의 DNS가 완전히 죽어있었음 — 상위 도메인 `policylab.co.kr`의 NS/SOA 조회부터 `SERVFAIL` (Google DNS 8.8.8.8 기준)
- 브라우저로 직접 접속해도 에러 페이지만 노출됨
- 부수적으로 발견한 문제: 챗봇 백엔드(`youthpolicy-chatbot-api`)가 정책 데이터를 가져올 때 참조하는 `https://yoon-kyoung.github.io/youthpolicy_contest/policies.json`이 GitHub Pages에 의해 커스텀 도메인(`on.policylab.co.kr`)으로 301 리다이렉트되는데, 그 도메인 DNS가 죽어있어서 나이/지역이 포함된 챗봇 질문에서 `fetch failed`가 발생하고 있었음
- 사용자 확인: DNS는 1~2일 내 연결될 예정이며, `POLICIES_URL`은 우회 수정하지 말고 `on.policylab.co.kr` 그대로 유지하기로 함

## 2. 챗봇 Solar API 연결 (OpenRouter → 직접 연결)

저장소: `youthpolicy-chatbot-api` (별도 백엔드, Vercel Serverless Functions)

- Upstage에서 Solar API 키를 직접 발급받아, 기존 OpenRouter 경유 방식에서 Upstage 직접 호출로 전환
- 변경 파일:
  - `api/chat.js`, `lib/extract.js` — 엔드포인트를 `https://api.upstage.ai/v1/chat/completions`로 변경, 모델 `solar-pro3`, 키는 `UPSTAGE_API_KEY`
  - `api/config.js` — `hasKey` 판정을 `UPSTAGE_API_KEY` 기준으로 변경, OpenRouter 전용이던 Nemotron 대체 모델 항목 제거
  - `api/moderate.js`, `api/compare.js`는 Solar와 무관한 별개 기능이라 기존 OpenRouter/Nemotron 연결 그대로 유지
- Vercel 프로젝트(`yoon19/youthpolicy-chatbot-api`)의 Production/Preview 환경에 `UPSTAGE_API_KEY` 등록
- 커밋 & `npx vercel --prod` 배포 완료, `/api/config`·`/api/chat` 응답으로 Solar Pro 3 직접 연결 정상 동작 확인
- 참고: 나이/지역이 포함된 질문에서 발생하는 `fetch failed`는 위 1번 DNS 이슈 때문이며 Solar 연결과는 무관 — DNS 연결되면 자동 해결 예정
